## 3. 代码核对新增的具体发现

### 3.1 财富的风险必填贯穿前后端

- `WealthArbitrator` 即使没有负向权重，也会从路径中选一个提醒方向。
- `WealthNarrativePlanner` 总是创建风险摘要，并按路径取风险文案。
- `WealthNarrativePlan` 要求 `mainRisk`、年度 `mainLimit` 非空。
- 前端类型同样必填，`WealthReportReader` 无条件访问风险内容。

因此，增加无风险分支涉及分析结果、正文结构、接口契约、前端布局和旧版本读取，不能只在文案文件删一句话。

### 3.2 固定剧情不只出现在年度标题

财富正文按 `year.first`、`year.second`、`year.later` 选择重点、留钱建议、观察事项、行动和过渡语；总论与三步行动路线也固定取文案。

整改必须同时覆盖总论、年度正文、跨年过渡和总结，否则只替换年度标题后仍会残留固定发展顺序。

### 3.3 前端也在增加结论强度

财富阅读页固定使用“钱主要从哪里来”“现实里出现这些情况，就说明方向正在发生”等标题。即使后端弱化句子，这些标题仍可能把观察建议包装成预测验证。

标题应随结论类型变化；普通观察建议不能写成“出现就证明预测成立”。

### 3.4 测试基础存在，但内容覆盖有限

- 当前财富黄金文件只有一个命盘、一个三年配置；主要检查年份、五路径集合及禁止证据键，且该样本的禁止键列表为空。
- 感情黄金集包含 6 个状态案例和 2 个合成边界；另有年度比较、单身版和快照测试。
- 已有语言测试，但不能证明所有文案分支都自然、准确或没有过度推断。
- CI 已运行前后端测试；当前触发为推送 `main` 或 PR，并非每次直接推送当前功能分支都会触发。

必须区分“测试存在”“测试覆盖当前问题”“最新提交已在 CI 验证”三个状态。

## 4. 三种整改路线比较

| 路线 | 做法 | 成本与局限 | 判断 |
|---|---|---|---|
| 只修文案 | 删除强句、换掉固定标题 | 小，但分支与依据脱节仍会复发 | 仅适合临时止损 |
| 分主题落实统一表达约束 | 保留计算，财富先行，再推广到事业与感情 | 中等；可逐阶段验收，能保留旧版本 | 推荐 |
| 重写统一评分引擎 | 三主题统一数据、权重、规则和文案 | 大；同时改变计算和表达，难定位变化原因 | 当前不建议 |

统一的是质量纪律、依据记录和表达检查，不是把财富、事业、感情分数混成一个全局总分。

## 5. 推荐方案：增加“结论允许表达什么”的约束

### 5.1 分开三个轴

1. **是否值得展开**：是否有相关依据、是否突出、是否与其他方向并列。
2. **倾向是什么**：偏有利、偏受限、有利与限制并存、没有明显支持。
3. **措辞能到什么程度**：在当前规则内突出、有限倾向、一般性说明，不设置“必然发生”的等级。

例如，一个维度可以同时是“重点”与“有压力”，不能因为净分不是高正值就不许成为重点；也不能因为排名第一就把它写成显著机会。

财富第一阶段保留既有计算权重作为可比较基线，不新造一套未经审校的分数。既有“6 分/3 分”状态只能作为工程初始分级，不作为现实概率，也不能单独绕过来源和反向依据检查。

### 5.2 结论与文案之间保存必要信息

下列是建议字段，不是已经存在的接口，也不要求第一阶段建立大型通用框架：

| 信息 | 用途 |
|---|---|
| 主题、年份、适用对象/状态 | 防止跨主题、跨年、跨场景借用结论 |
| 内容性质 | 区分规则推断、用户提供的现状、普通建议、观察例子 |
| 关注方向、倾向和表达等级 | 让选择文案时不能绕过结论强弱 |
| 支持、限制的证据键及来源 | 追查是哪一项依据导致该句话；相同来源不能换个名称重复计数 |
| 文案标识、规则/策略/文案版本 | 比较修改前后为何变化，并保留生成快照 |
| 未达到更强表达的原因 | 供内部审校，默认不把技术原因长篇展示给用户 |

第一阶段采用主题专用评估与小型验证器即可；另外两个主题迁移后，再提炼真正共用的部分。

检查必须覆盖正文而非只检查元数据。每个获准文案分支也要审校：单纯在数据上标记“弱”，但文字写“收入主要来自这里”，仍应判失败。

### 5.3 没有突出信号时怎么交付

- 不强造“最旺方向”，不说“今年不会有大事”。
- 正常呈现五路径的有依据差异，包括限制、并列和延续，不因为没有强机会就把整份报告变成空答案。
- 普通建议可以保留，但必须与个性化判断区分，不能拿通用建议冒充命盘结论。
- 无依据的具体断言应省略；若某类有效命盘整份只剩通用建议，应列为内部内容覆盖不达标，先修覆盖，不作为付费合格报告放行。
- 无负向依据，只表示本套规则未形成特定风险判断，不表示现实没有风险。

这遵守“不交付空答案”的要求，同时不以编造结论换取覆盖率。覆盖率和依据真实性需要分别验收。

## 6. 整改批次、范围和验收

### 第一批：财富质量整改最小闭环（P0）

目标：同样的计算输入，输出不夸大、不强造风险、不按年序讲固定故事，同时旧报告照常可读。

建议顺序：

1. 冻结现有样本和计算结果，先补当前缺陷的回归用例。
2. 建立财富结论的方向、倾向、表达约束及文案分支检查。
3. 支持无风险、并列、相对领先但不突出，不再强制把排序翻译成机会。
4. 按真实年度差异重做总论、五路径说明、留钱判断、年度建议及过渡；不改变原始权重。
5. 新建内容版本，接通接口、阅读页、版本判断和旧快照读取。
6. 输出新旧样本对照，由用户审核通俗程度和内容价值，再决定扩大范围。

主要改动：财富评估/仲裁/正文模型与文案，`ReportService`，接口契约，前端报告类型、阅读页与版本分流，相关测试。

不包含：重写排盘、改旺衰、增加主题、扩产品年限、接支付、上线专业版。

验收标准：

- 无负向依据时，无风险摘要和年度风险段落；前端无空卡片、空引用或错位。
- 所有收入方向偏弱或并列时，不输出唯一明确增收主线；存在限制时不能被“主要方向”标签掩盖。
- 同一年度的数据不因处于报告第几年而改变判断；年份序号只用于排版。
- 相邻年没有变化时允许延续；依据来源变了但分数相同时，能解释差异，或只陈述相应边界。
- 增加限制依据不能无故把结论措辞升级为更有利。
- 一般观察不被页面标题写成对预测的验证。
- 旧版财富、旧版事业和两类感情快照保持可读；新报告不会改写旧原文。

### 第二批：统一事业与感情的表达纪律（P1）

- 事业：将问卷现状、年度规则结论、一般行动建议分开；去掉按年份序号预设的成长过程。
- 感情：复核当前各倾向分支是否有充分依据，不因结构较完善就豁免；保留单身今年重点及无风险机制。
- 统一短句、明确主语、无过度断言的测试，不通过增加术语和长篇证据来制造专业感。
- 专业版的即时止损可独立前置：建议将事业专业版入口标为未开放，后端同时拒绝新建；已有报告不删除。这是建议变更，待确认后实施。

验收标准：改变事业问卷不改变原始年度计算；换关系状态不改变同年维度计算；文案不把用户自述说成算法发现；三个主题都满足同一套表达边界。

### 第三批：敏感性与权重治理（P1，诊断可以提前）

- 在可达旺衰阈值附近建立真实命盘边界集，并以合成输入隔离测试阈值行为；两类用例不能混为现实证据。
- 记录哪些规则、路径、倾向及最终句子受边界影响。不能把两份不同出生输入之间的所有变化都归因于旺衰阈值。
- 不先修改旺衰分类。若发现仅靠边界分类就触发强结论，优先限制这些结论的措辞；改分类或连续模型需另立评审。
- 跟踪不同证据来源的贡献，检查重复计分、某类来源长期压过其他来源、排名翻转和无风险占比变化。
- 每次只改变一个可说明的规则或权重组，记录预期影响、实际差异和人工审校结论。

验收标准：权重变更能列出受影响案例与原因；测试不能以“所有分数都不变”为目标，也不能简单接受新的全文快照作为正确答案。

### 第四批：历史修正和商业化前置机制（后续）

- 旧原文保留，发现严重错误时可追加说明和关联修正版。
- 修正版沿用原报告分析年份、状态与年限，另记修正版本、原因和时间；不偷换成新年度报告。
- 建议产品缺陷修正不再次收费、不消耗会员额度；这属于待确认的权益例外，不在本次默认实施。
- 长期数据库、恢复验证、真实支付、订单与生成失败处理、会员额度仍是上线前独立工作，不应被内容整改遗漏。
- 专业版可以继续暂缓；不必为了先售卖合格通俗版而强行开发专业版。
- 不把 LLM 预研放进本轮任务。

## 7. 测试与回归应该怎样补

采用“结构化断言＋精选正文快照＋人工内容评审”，不只做整篇文本对比。

| 场景 | 主要检查 |
|---|---|
| 全路径没有突出支持 | 不虚构唯一强方向，不转成“现实没有大事” |
| 有利和限制同时明显 | 两面都保留，不被净分抵消 |
| 没有负面依据 | 不生成推断性风险，前后端完整处理空风险 |
| 同源证据重复或换键 | 不借多个标签伪造独立支持 |
| 主辅并列 | 不用固定枚举排序伪造明显差距 |
| 同分不同依据 | 差异可追溯，不靠随机换词 |
| 相邻年度相同 | 能表达延续，不强制制造起承转合 |
| 同一年在不同年限报告中 | 年度判断保持一致；跨年汇总允许因范围变化而变化 |
| 旺衰阈值附近 | 分开检查分类、规则与措辞的变化 |
| 改事业问卷或关系状态 | 计算与场景解释的边界不被破坏 |
| 新旧快照共存 | 旧原文不变，新版本正确分流，未知版本不误当事业 |
| 财务/医疗/关系绝对措辞 | 检查已审校的允许/禁止表达，保留否定语境，不仅粗暴搜关键词 |

固定分析日期、时区与规则版本；回归数据采用测试命盘或经授权脱敏的数据，不上传真实个人报告到公开 CI 日志。

样本集应按上述风险覆盖逐步扩充。建议第一批至少包含一组多样的完整命盘和覆盖所有边界的合成输入；样本数量不是预测准确率证明。

CI 在现有测试之上增加语义检查和结构化差异产物。通过 PR 触发即可利用当前工作流；若需要功能分支直接推送也验证，再单独调整触发条件。对旧结果的预期变化必须审查，不盲目批量更新快照。

## 8. 改动与影响评估

| 范围 | 预计程度 | 主要风险与控制 |
|---|---|---|
| 排盘基础与原始权重 | 第一批不改 | 保留基线，便于区分计算变化和表达变化 |
| 财富后端内容结构 | 中等 | 风险可空、主辅非强制、依据关联，需要完整回归 |
| 前端页面 | 小到中等 | 适配可空风险和不同结论类型，沿用现有视觉，不重新设计整站 |
| 接口契约 | 中等 | 前后端同批支持新内容版本，先定义再实现 |
| 历史报告 | 中等兼容风险 | 保留旧读取逻辑，新版独立结构，禁止批量覆盖旧正文 |
| 数据库存储 | 需验证 | 现有正文为 TEXT，增加审计内容后测实际字节大小，并在 MySQL 验证，不能只靠 H2 测试 |
| 支付与额度 | 本批不接入 | 内容版本变更不擅自更改价格或权益 |

建议新版财富采用独立内容版本（如 `wealth-narrative-v3`，名称待实施确认），不直接改变旧 v2 的含义。先部署可读取新旧版本的代码，再启用新版生成；回滚时停用新版生成而非退回无法读取新快照的旧代码。
