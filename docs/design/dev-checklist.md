# 开发自检清单（防复发）

> 目的：本清单收录项目开发过程中「编码/测试阶段未发现、交付后才暴露」的 bug 类型，作为后续开发与提交前的强制自检项。**每次改动（功能/修复/重构）提交前逐条自查**，命中即补测试或修正后提交。

## 1. 状态与数据流（历史最高频区）

- [ ] 页面依赖排盘结果：是否复用 `useBaziWithFallback`（当前结果 → 最新历史兜底）？**禁止**新页面直接裸读 zustand store 而不做兜底。
- [ ] 改动涉及内存态（zustand / useState）时自问：**刷新页面后这个数据还在吗？** 需要长期保留的走 IndexedDB / localStorage / 后端，页面必须有兜底来源。
- [ ] 展示层不混用「当前结果」与「历史记录」两套来源，避免"有记录却显示空"。
- [ ] 组件重新挂载（切路由/刷新）后，状态应能从持久化或接口恢复，且展示与数据一致。

## 2. 真实交互路径（自动化测试盲区）

- [ ] 分享/导出类功能：**用户实际拿到的是什么**（剪贴板是文字还是图片文件、下载文件多大）？测试断言最终产物，而不是只断言生成函数有输出。
- [ ] 页签 / 分段控件 / 开关：切换后**关联内容是否真正更新**？写回归测试断言切换前后 DOM 内容变化。
- [ ] 每个状态下入口/按钮是否可见、可点、有反馈：登录/未登录、mock/http、会员/非会员、空态/加载态/错误态。
- [ ] 按钮文案与实际行为一致（如「立即开通」在 mock 模式应明确提示，而不是静默失败或报错）。

## 3. 双模式测试矩阵（mock / http）

- [ ] 改动涉及条件渲染或 API 调用时，覆盖受影响象限：`mock×已登录`、`mock×未登录`、`http×已登录`、`http×未登录`。
- [ ] **登录态只由 token 驱动**；禁止用 `VITE_API_MODE === 'http'` 当作"是否登录"的代理条件。
- [ ] 联调模式差异要在 UI 上可见（如 mock 模式标注"演示模式"），不能静默吞掉。

## 4. 运行态与环境

- [ ] **改了后端代码必须重启后端进程再验证**（历史教训：JVM 运行中按需加载新编译类，与容器旧 Bean 错位 → 接口 500，而全新进程一切正常）。
- [ ] 接口改动先改 `contracts/openapi.yaml`（契约先行），前后端字段名保持 camelCase 一致；联调前先看契约。
- [ ] 沙箱/受限环境无法验证时（Mockito attach、node_modules 写权限、localhost 访问），明确标注"需沙箱外/本机验证"，不要当作已通过。
- [ ] 数据库变更：加列必须带兼容默认值；禁止破坏性变更；`schema.sql` 与数据库设计文档同步。

## 5. 视觉与体验走查（人工）

- [ ] 按钮成组等宽、顶栏左右对称；按钮/图标与其文字垂直居中对齐。
- [ ] 空态/加载态/错误态文案可理解且不误导（如"登录后可用"出现在已登录状态）。
- [ ] 动效 < 300ms，尊重系统"减弱动态"；按压有反馈。
- [ ] 刷新后视觉状态与数据状态一致（不出现"显示已登录但卡片引导去登录"）。

## 6. 需求与场景质疑

- [ ] 功能交付前自问：**真实用户会用吗？**（历史教训：每日运势分享是伪需求，交付后复盘砍掉）。
- [ ] 合规红线：文案温和参考型、不绝对预测、保留免责声明；不输出医疗/投资/婚姻等确定性建议。
- [ ] 定价/会员等商业字段由后端常量出，前端只展示。

## 7. 测试与交付纪律

- [ ] 每次改动有对应测试；修 bug 先补回归测试（或同提交内补），不允许"只改代码无测试"。
- [ ] 提交前全量验证：前端 `npm test` / `npm run lint` / `npm run build`；后端 `mvn test`；CI 双端绿。
- [ ] 重构/优化不得引入次要缺陷：改动后跑全量回归，不只跑改动的用例。
- [ ] 文档先行：功能改动先更新对应设计文档并标记进行中，交付后改已交付并同步 `outputs/`；变更日志只留最近一条。
- [ ] 提交信息按「类型(端): 摘要——关键细节」格式，便于 git log 回溯（本清单即由 fix 提交归纳而来）。
