# 感情命书 v1：计算、文案与验收边界

## 产品范围

感情命书只开放通俗版。2026-08-27 起，新生成的单身报告使用“今年重点＋明年简短参考”；交往中、已婚继续展示当前年份与之后两年。用户仍只选择一次当前关系状态：

- `single`：单身或尚未确定关系；今年详细回答认识机会、继续发展和需要留意的事情，明年只有简短比较，不默认展示第三年。
- `dating`：已确认交往关系；回答是否适合继续发展、分歧如何处理。
- `married`：已婚或长期共同生活；回答如何减少消耗、安排共同生活与重要决定。

专业版保留产品位置但不可生成。接口返回 `RELATIONSHIP_PROFESSIONAL_NOT_AVAILABLE`，不会自动改成通俗版，也不会写入报告记录。

## 数据流边界

```text
出生信息 + 命盘
      ↓
关系事实提取
      ↓
五个维度逐年评估
      ↓
年度与三年主次裁决
      ↓                 当前关系状态
三年计算结果 ──────────────┬──────────
                            ↓
                     状态专属通俗文案
                            ↓
                       保存并页面阅读
```

当前关系状态由服务层用于选择产品年份范围和文案版本。事实提取、权重、主次排序、并列标记、风险选择和年度变化均不得接收该字段。同一命盘在相同年份范围内，这些计算字段必须完全一致；两年与三年的总计不能直接混比。单身总论只取当前年度，不用两年汇总重点替代今年重点。

## 五个维度

| 维度 | 回答的问题 |
|---|---|
| 关系连接 `connection` | 是否更容易注意、认识或靠近某个人 |
| 回应与表达 `response` | 话能否说清，彼此能否认真回应 |
| 日常配合 `daily_cooperation` | 时间、见面和生活节奏能否互相配合 |
| 矛盾与边界 `boundaries` | 分歧是否容易升级，界限能否守住 |
| 长期稳定 `stability` | 关系能否落到持续、具体的共同安排 |

每个维度同时保留支持证据和限制证据。主次维度按显著程度选择，不能为了让结果更积极而忽略强烈的限制信号。并列时采用固定维度顺序，并保留 `focusTied=true`。

## 初版证据表

| 命盘或运势事实 | 用途 |
|---|---|
| 原局配偶星组显现或藏于地支 | 关系连接、长期稳定 |
| 原局食伤、印星组 | 回应表达、日常配合 |
| 流年配偶星组、食伤组、印星组 | 当年的连接、表达和配合重点 |
| 流年比劫组 | 平等、个人空间与边界议题 |
| 流年非配偶星的财官组 | 具体安排与长期稳定议题 |
| 流年地支与日支相合 | 日常配合、稳定、回应 |
| 流年地支与日支冲、害、刑、破 | 边界、稳定或配合方面的限制 |
| 流年与其他原局柱关系 | 次一级的连接、配合或边界信号 |
| 当前大运十神组与流年关系 | 三年背景，不单独决定现实事件 |

男性以财星组、女性以官杀组作为配偶星组。它只表示关系议题受到注意或被激活，不能据此断言结婚、分手、忠诚状况或具体人物身份。

## 权重含义与限制

支持权重、限制权重和显著权重用于让规则可检查、可排序、可回归。它们不是统计样本计算出的概率，不代表“有多少概率恋爱或结婚”，也不构成现实事件保证。通俗版页面不展示数字。

没有负面证据时，三年风险和年度限制必须为空；不得为了让报告显得完整而编造警告。`quiet` 表示该维度当年不是重点，不等于计算失败或资料不足。

## 文案规则

三种状态分别维护完整文案，不通过替换“对象、伴侣、配偶”等名词生成。原 `relationship-narrative-v1` 每年固定包含：

1. 一个核心判断；
2. 两个现实中可以观察的信号；
3. 两条明确到“谁做什么”的建议；
4. 一句与下一年的衔接。

禁用没有信息量或无法由规则支持的说法：

- 现有证据不足、先观察再判断、现在卡住了、卡点；
- 正缘、烂桃花、第三者、不忠；
- 必定结婚、一定分手或其他确定性事件断言；
- 复盘、赋能、承接、推进、协作节点等工作场景套话。

## 接口与兼容

### 2026-08-27 单身今年重点版

- 新单身快照版本：`relationship-single-v1`。原 `relationship-narrative-v1`（包括旧单身三年快照）继续使用旧解析与阅读组件，不裁剪、不重算、不回填。
- 服务层使用 `ReportHorizon.RELATIONSHIP_SINGLE_PRODUCT`（2 年），五个维度仍完整计算；共享最短 2 年、最长 5 年的技术边界不变，财富及其他关系状态的产品范围不变。
- `RelationshipSingleNarrativePlanner` 只用当前年度选择结论、正文和风险；下一年独立做相邻年比较。更改下一年不能改写今年的结论或章节。
- 新内容含 `thesis`、`summary`、`currentYear`、`outlookYear`、`sections`、`outlook`、`readingNote`，并保留两年 `evaluations` 与 `evidenceKeys` 供核对。保存边界校验年份、状态、完整章节、原始计算和依据引用。
- 正文按“今年有没有认识人的机会”“认识后能否继续发展”“今年需要注意什么”组织。无当年限制依据时省略第三节，不编造警告。五维完整计算不等于必须重复展示五张卡片。
- 使用条件句同时兼顾“尚无接触对象”和“已在了解某个人”，不增加问卷，不把相处示例当成计算出的事实。
- 明年最多选两项重要维度变化，保留同一维度支持与限制的相反变化；相同结果明确延续，依据替换不宣称变好。没有未来第三年内容。
- 生成页选单身后显示“今年重点＋明年参考”，未选关系状态不预先承诺三年；阅读页的年份取保存快照，不随打开日期漂移。
- “今年”仍是年度解读，不是未来十二个月，也不单独预测剩余月份。文案优化不代表预测准确性已得到现实验证。
- 本轮不修改价格、支付、会员权益；联调入口仍明确当前不扣费。

审核样稿见 [单身今年重点样稿](../samples/relationship-single-current-year-review.md)。

### 2026-08-27 年度差异解释修复

旧版年度核心判断只由状态、主维度和倾向选句，因此不同流年可能输出同一句。
现在在计算与文案之间使用 `RelationshipYearComparison` 和 `RelationshipAnnualNarrator`：

- 比较五个维度的支持、限制及依据来源，不以净分相同代替“无变化”。依据标签中的年份文字不参与比较。
- 既检查当前主维度，也解释上一主维度为何退居其次；随后考虑主要风险及其他变化。
- 原局固定背景不逐年重新解释。没有变化时明确说明延续，不轮换同义句，也不按“第几年”安排关系阶段。
- 年度判断最多三句、总长不超过 120 字；每句继续遵守 48 字短句限制。最多解释两项关键变化，不能只写支持而丢掉同维度增加的限制。
- 支持与限制权重相同但来源改变时，解释具体侧重点的变化，不直接宣称更好或更坏。
- 观察提示与建议由当年主维度及限制选择，使用“是否”等可观察表达，取消与年份序号绑定的固定故事。
- 下一年提示使用相邻年份比较，并保持简短；最后一年改为阅读提醒，不推演未计算的下一年。
- 产品仍只生成三年，技术上的二至五年输出不再把第四、五年写成“第三年”。

计算规则、权重、主次裁决、风险选择、收费及关系状态边界均未改动。
JSON 字段结构和 `relationship-narrative-v1` 内容类型保持兼容；读取旧快照不会重新生成或去重旧文案。
新版验收应使用相同输入重新生成，不能只刷新已有报告链接。

修复对照见 [年度差异修复样本](../samples/relationship-annual-difference-fix.md)。

- 内容版本：`relationship-narrative-v1`。
- 缺少状态：`RELATIONSHIP_CONTEXT_REQUIRED`。
- 非法状态：`RELATIONSHIP_STATUS_INVALID`。
- 请求专业版：`RELATIONSHIP_PROFESSIONAL_NOT_AVAILABLE`。
- 旧事业、旧财富与财富 v2 按各自 `contentVersion` 继续反序列化，感情 v1 不得落入旧事业结构。
- 报告保存的是生成当时的完整内容快照和最小状态上下文，之后文案升级不会改写旧报告。

## 规则变更审查清单

- 新证据是否有稳定键、来源事实和明确维度？
- 状态字段是否仍只进入文案层？
- 同一证据是否在同一维度被重复计数？
- 主次是否按显著程度而不是净正向分数排序？
- 没有负面证据时是否继续省略风险？
- 新文案是否明确主语、对象和可观察结果？
- 是否出现确定性事件、人物身份或忠诚判断？
- 男、女命盘和三种状态黄金样本是否全部通过？
- 并列、冲突关系、相合关系和无负面证据边界是否仍有覆盖？
- 430px 与桌面宽度是否无横向溢出，纸张与背景是否对齐？
