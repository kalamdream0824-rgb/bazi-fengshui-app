- 对应任务：第一批整改任务 2 定义规则、任务 4 实现独立判断、任务 5 实现年度比较、任务 6 实现正文、任务 7 接入后端生成与快照、任务 8 接入前端阅读；日期：2026-08-29。
- 状态：**后端 v3 生成、生成前校验、版本化快照、前端页面和任务 9 系统验证已完成；真实 MySQL 三年测试样本已往返，`TEXT` 容量余量风险仍保留**。
- 前置基线：`../samples/wealth-v2-remediation-baseline-2026-08-29.md`。
- 范围：财富通俗版、页面阅读、产品三年；不引入 LLM、问卷、专业版、支付或新主题。
- 不改变：排盘、旺衰分类、现有财富事实和每条原始权重。新增的分级是表达约束，不是新算命模型，不提供现实概率或准确率保证。

## 1. 核心决定

1. **收入方向、正负倾向、表达强度分别判断。**排第一不等于机会强；需要认真说明的也可能是限制。
2. 五条路径全部分析，但不强制有唯一主方向、辅助方向或风险。
3. 没有负向依据就省略具体风险，不写成“今年不会损失”。
4. 支持与限制都存在时保留两面，不让净分掩盖限制。
5. 同年判断不依赖“第一年、第二年、第三年”；相邻年相同就允许延续。
6. 一句话所依据的年份、判断、事实来源和文案分支必须能追查；仅加元数据不能代替正文审校。

## 3. 每年五路径的判断规则

五条路径固定为稳定收入 `stable_income`、靠能力赚钱 `skill_income`、项目和额外收入 `project_income`、合作收入 `cooperation_income`、把钱留下 `retention`。固定展示顺序不是优劣排序。

### 3.1 支持和限制不相互抹除

对同一年度、同一路径：

- `supportWeight`：现有正向权重之和。
- `limitationWeight`：现有负向权重绝对值之和。
- `netWeight = supportWeight - limitationWeight`。
- 新层保留旧权重逐项记录，不把重新分组当成调分机会。

| 条件 | `stance` | 允许传达的意思 |
|---|---|---|
| 支持 = 0，限制 = 0 | `quiet` | 本套规则没有形成该路径的具体判断，不代表现实无事 |
| 支持 > 0，限制 = 0 | `supportive` | 该路径存在支持，不等于一定增收 |
| 支持 = 0，限制 > 0 | `restricted` | 存在需要说明的限制，不等于一定亏钱 |
| 支持 > 0，限制 > 0 | `mixed` | 有支持，也有条件或限制；正负都要交代 |

`mixed` 不随净分正负改成单面有利或单面不利。`quiet` 不生成没有来源的具体事件判断，可作简短方法说明；不能整页重复“证据不足、先观察”。

### 3.2 表达强度

`strength` 约束有利判断最多说到什么程度，**不是“预测置信度”**。限制的存在通过 `stance` 和负向依据保留，不因为表达等级低就隐藏。按下表从上到下判定：

| 条件 | `strength` | 措辞边界 |
|---|---|---|
| 无任何支持和限制 | `none` | 只能说明覆盖边界，不能推演事件 |
| 存在限制，或净分 < 3，或来源尚未完整核实 | `limited` | 只说有限倾向或具体限制；不能写“主要收入就来自这里” |
| 净分 ≥ 6、无负向、至少两个正向家族，且通过下述独立来源检查 | `pronounced` | 可说“在这份分析里更值得关注”；仍不许说必然发生或保证收入 |
| 净分 ≥ 3、无负向、来源可核实，但不满足上一行 | `supported` | 可作为有依据的方向展开；不包装成唯一或显著机会 |

3/6 分沿用旧分级的工程起点，不是新获得的现实统计阈值。不得单凭净分达到 6 就进入更强表达。

独立来源检查采用保守口径：

- 保留四个旧 `family` 值，供对照原计算；来源归组时把 `NATAL_STRUCTURE` 和 `NATAL_COMBINATION` 都归为原局组，另有流年、大运组。
- 更强表达至少需两条来自不同来源组的支持，且它们展开后的根事实集合不重叠。单条组合依据含两个组，不算“两条独立支持”。
- 同一原局条件派生的单项与组合项不能算两个独立来源；把同一依据改名也不能升级。
- “独立”仅指工程上的来源不重复，**不声称统计独立**。无法确认来源时从严限制表达，不补造根事实。
- 不改变旧权重总和。即便多个旧计分项源于同一条件，也只在表达升级检查中防止重复充数，评分治理另立批次。

`reasonCodes` 供内部审校，不整段显示给普通读者：

| 值 | 使用条件 |
|---|---|
| `no_evidence` | 正负均为零 |
| `limited_net_support` | 存在依据但净分 < 3 |
| `single_origin` | 有支持，但找不到符合要求的两组独立来源 |
| `has_limitations` | 限制权重 > 0 |
| `legacy_provenance_unresolved` | 旧计分项来源存在尚未核实的完整性问题，禁止升级表达 |

原因码记录实际限制表达升级的原因，不是所有符合条件的标签全集，可以同时保留多个。例如净分为 1 时可记录 `limited_net_support`，不必再重复标注单来源；正负并存时优先记录 `has_limitations`。来源未核实必须记录相应原因，且不得对外输出超出已核实部分的解释；若缺失必要根事实或无法证明分支许可，应在生成校验时失败，而不是用该标记允许错误内容通过。

### 3.3 收入关注方向：允许无主线或并列

只对四条收入路径排序，留钱路径单独完整说明。

1. 候选门槛为净分 ≥ 3，且用于结论的来源可核实。低于门槛不因排名第一而成为主要赚钱方向。
2. 没有候选时，`focus.state = none`，主辅数组均为空。正文仍说明有依据的差异或限制，不强编增收主线。
3. 最高分只有一条，`state = leading`；主候选只有该项。剩余合格项中最高分的全部并列项可作为辅助候选；没有就留空。
4. 最高分有多条，`state = tied`；保留全部并列主候选，辅助为空，不用顺序硬拆主辅。
5. 净分合格但正负并存的路径可以入选，不过必须保留 `mixed / limited`，在同一判断中说明限制。

`leading` 只是相对排序关系，页面标题和正文的强弱仍由 `strength` 决定；低分并列不能进入“并列强机会”。其他有压力的路径仍在五路径说明、留钱段或风险段展开，不因没进收入候选而消失。

### 3.4 风险：显式可空

- 仅从限制权重 > 0 的路径中选择年度风险；没有则 `risk: null`，不是缺字段、空对象或“暂无风险”占位文案。
- 有多个时优先选限制权重最高者。若并列，可按既定路径顺序选一项用于紧凑展示，但标题只能说“需要留意的一项”，不能说“唯一风险”或暗示该项严格更严重。
- 所有路径的限制仍在对应路径正文中保留，不能因只展示一项年度风险就删掉其他限制。
- 风险必须引用该年该路径真实负向计分项。一般理财常识不得伪装成特定风险。
- 三年均无负向，`riskSummary: null`；只在部分年份有负向，摘要明确写适用年份，不能扩大为三年共同风险。
- 任何 `null` 都不意味着现实安全。阅读说明可简短说明分析边界，但不要反复用免责声明充篇幅。

## 4. 数据结构和引用关系

| 层级 / 字段 | 职责与数量 |
|---|---|
| 响应外层 | 保留报告编号、姓名、主题、版本、状态和生成时间；本草案仅 `wealth / plain / ready` |
| `content` | 分析日期、时区、三种版本标签、总论和三年内容 |
| `thesis`、`summary` | 总重点和摘要；引用实际适用的年度判断，不另造三年剧本 |
| `pathSummaries` | 恰好五项，逐路径关联三年的判断；不把多数年份状态冒充三年一致 |
| `years[].facts` | 最小根事实表：`id / kind / code / value`；类型为原局、流年、大运，不含未经用户提供的现实经历 |
| `years[].evidence` | 每条旧计分项的 `id / path / ruleKey / factKey / family / rootFactIds / weight`；非零整数权重 |
| `years[].decisions` | 恰好五项，保存正负权重、净分、倾向、表达等级、支持/限制引用和原因码 |
| `years[].focus` | 无突出收入方向、唯一相对领先或并列三个互斥分支 |
| `years[].overview / income / retention` | 年度总判断、1–2 个收入说明段、留钱说明段；不能借数量限制省略关键反向条件 |
| `years[].risk` | 一项带负向引用的说明或 `null` |
| `years[].observations / actions` | 0–2 个观察例子、1–2 个行动建议；不可把普通建议当命盘事实 |
| `years[].comparison` | 到下一年的差异及说明；末年为 `null` |
| `route`、`readingNote` | 1–3 条有依据或明确标为一般建议的行动路线、简短阅读边界 |

### 根事实与旧计分项怎样连接

- `factKey` 保留旧依据键，`ruleKey` 标识产生该路径权重的规则分支，两者不能混同。
- `rootFactIds` 指向实际参与该分支的根事实。例如原局组合应展开其参与条件；不能只把组合名称当成独立根事实再与原局单项重复计数。
- 一条旧依据作用于两个路径时，两条计分记录可以共享根事实，不能因此在同一路径多算一次。
- 同一年度、同一路径的同一规则与来源不得重复登记；已知派生关系不得用新 ID 隐藏。
- 无法找到根事实是适配错误，不通过伪造占位 ID 来满足 Schema。任务 4 已实现独立来源映射，现有事实提取和权重输出仍保持基线。
- 报告只保存解释所需的事实及引用，不新增身份证件、联系方式、现实收入等资料。客户端只展示普通正文，不默认展开规则键或分数。

任务 4 的完整分析入口为 `WealthV3Analyzer.analyze(chart, contexts)`，同时使用原局地支和当年大运上下文核实关系。只有 `WealthYearFacts` 的局部入口无法核实关系的另一地支时，保留已知根事实及原分数，标记 `legacy_provenance_unresolved`，限制表达并排除该路径的收入候选；不从描述文字反推缺失资料。完全未知的计分来源、值冲突或错误关系直接报错。

局部入口的负向计分仍保留，内部风险选择也可能引用待核实项，不能把“没有被选中”当作删除负向依据的理由。**内部判断不是可发布正文**：生成器拒绝带有待核实来源的输入；任务 7 已把完整来源分析、正文校验和 `WEALTH_CONTENT_INVALID` 失败响应接到业务入口，校验失败不保存报告。当前 15 组完整出生链路样本的 46 个年度没有待核实来源；这不是对所有合法输入的穷尽证明。

### 统一文字块 `Block`

每块保存 `id / kind / text / templateId / years / decisionIds`：

| `kind` | 意义 | 必须避免 |
|---|---|---|
| `interpretation` | 依据当前规则形成的判断，必须引用至少一个对应年份的判断 | 有 ID 却无合适依据，或文案比许可等级更强 |
| `observation` | 读者可以留意的现实例子，允许关联判断 | “出现这个现象就证明预测正确” |
| `general_advice` | 一般建议，不冒充个性化结论；可以关联适用判断 | 暗示已知用户工资、职业、债务或行为 |
| `method_note` | 阅读和方法边界 | 把没有识别到信号说成未来没有事件 |

通用建议和方法说明可以没有判断引用，但必须有适用年份。每块最多 240 字符只是传输上限，不是写作目标；正文仍优先短句，明确谁、什么事情、为什么以及要做什么。分数、家族、净值等内部术语不进入通俗正文。

## 5. 年度比较：比较依据，不比较报告序号

每年判断先独立完成，再比较相邻两年。计算和文案选择函数不得以数组下标决定机会、风险、先后成功或收入增长。

比较至少包括：

- 每条路径的支持与限制变化，不能只看净分。
- 来源规则、实际事实值和来源关系变化。年度 ID 自然变化不算业务变化；同一键的事实值变化不能漏掉。
- 关注候选、倾向与表达等级是否因此改变。

规范化比较时，去掉记录 ID 中纯粹的年份前缀，保留 `path / ruleKey / factKey / family / weight` 和根事实的 `kind / code / value`。只更换展示文案或数组顺序不算计算变化；流年事实值、关系条件或大运实际变化必须保留。

`comparison` 约定：

- `toYear` 必须是下一年；最后一年为 `null`。
- `direction = unchanged` 时 `changes = []`，允许写“下一年仍以这个方向为主”等符合强度的延续，不制造变化。
- `direction = changed` 时至少一条路径差异。每条记录保存支持/限制差额、新增依据 ID、移除依据 ID。
- 新增引用属于下一年，移除引用属于本年；同分但来源变化允许差额为 0、增删引用非空。
- 比较段同时引用相关两年的判断。收入段只说本年，不因本年在不同报告里排第几而变化。
- 没有现实记录时，不写“前两年已经验证有效”“赚到之后再扩大”等前提已成立的话。

技术二至五年扩展时仍遵守相同年度不变量；公开 v3 Schema 保持三年，未来扩产品时再评审对应字段上限、摘要和页面长度。

### 任务 5 已实现的比较口径

- `WealthAnnualComparator` 接收已完成的两个年度判断，不改事实或权重。比较键为 `path / ruleKey / factKey / family / weight` 加所引用根事实的 `kind / code / value`；根事实按集合处理。
- 记录 ID 只用于查找事实和保留引用，不参与相等性判断。因此年份前缀、别名或数组顺序不会造成假变化；实际规则键、来源键和事实值中的内容不会被粗暴删掉年份后比较。
- 仅比较参与当前计分与判断的事实。未参与任何计分的事实或纯年度标题变化，不能单独制造某条路径的变化。
- 支持/限制差额均为“下一年减本年”。同一计分项的权重、来源或根事实变化时，移除本年旧记录并新增下一年记录，即使其业务键相同也保留两侧引用。
- 逐路径比较倾向、表达等级、原因码及关注角色；原来独自领先、后来并列时，该路径自身分数没变也应记录。此类 `changes` 可为零差额、无增删引用，具体前后状态从两年判断读取；不能虚构计分依据填满数组。
- `changed` 只表示上述数据或判断状态不同，不表示变好、变差或现实事件必然发生。来源由待核实变成已核实也会改变表达许可，后续文案必须区分这种权限变化与实际条件变化，且不得发布未核实的必要来源。
- `analyzeWithComparisons(chart, contexts)` 返回内部年度判断及比较，原 `analyze` 入口和每年判断不变。同一对年度在不同起始年/总年数中的比较不变；某年成为末年时，只有其到下一年的比较变为 `null`。
- `WealthComparison` 保持纯内部差异，不含 `reading`；任务 6 新增的 `WealthNarrativeV3.Comparison` 将差异与实际解释、适用年份和判断引用组合，仍不直接作为正式报告发布。

## 6. 结构合法之外，还必须校验的语义

任务 4–6 在独立层校验判断、来源、比较以及当前新草稿的文案许可、年份和引用；任务 7 已把相同生成器和 `validateDraft` 校验接到正式财富生成入口。校验只作用于新生成内容，不在历史读取时重建正文。

以下是整份报告必须满足的约束。任务 6 实现比较说明、正文许可、适用年份及全零覆盖拦截；任务 7 已接入业务生成、错误响应和保存。文案许可详见 `wealth-v3-copy-license.md`：

1. 每年恰好五种不同路径；年份连续且与分析日、年限一致。
2. 所有 ID 唯一、引用存在且作用域正确。普通年度正文不引用别年判断，比较和三年总论明确适用范围。
3. 每个支持引用的权重大于零，限制引用的小于零，且属于同年度同路径；汇总分数等于这些计分项之和。
4. 根事实与规则分支真实对应；同源派生或改名不得提高独立来源数量。
5. `stance / strength / reasonCodes / focus` 符合第 3 节，主辅不重叠，不遗漏并列候选。
6. 年度风险和风险摘要可空但不遗漏实际负向条件，不引用其他路径或年份凑风险。
7. 年度比较由真实差异产生；同分不同依据、同依据不同年序均有独立测试。
8. 文案分支建立许可表：支持的倾向、表达等级、依据条件和年份范围。验证器检查 `templateId` 与判断匹配，人工审校实际句意。
9. 不能用 `general_advice` 标签包住具体预测以绕过检查；仅有通用建议的完整报告不能作为付费合格内容放行。
10. JSON Schema 不能证明中文自然、规则合理或现实预测准确。必须结合实际生成样本阅读和差异审查。

**覆盖不足的处理：**合法输入若整份只能生成通用建议，应记录为内部内容覆盖不达标，不回退成一份“先观察再判断”的 `ready` 报告。当前业务入口返回 `WEALTH_CONTENT_INVALID`，且不保存不合格新正文。本轮不新增付费扣款规则，也不承诺支付能力已接入。
