## 输入边界

`WealthNarrativeWriter.plan` 只消费已完成的年度判断和分析日。正常调用链由完整出生输入经 `WealthV3Analyzer.analyze` 得到判断，不由客户端提交分数或文案。

生成前按原事实和计分项重新核对表达策略，拒绝与策略不一致的判断、尚未核实的来源、错误分析起始年、非连续年份以及不在二至五年范围内的输入。整份五路径全部无依据时拒绝生成；不能把一般建议凑成命书。弱信号可以输出内部审校草稿，但不等于付费质量已经过关。

输入来自已核实计算链是前提。正文校验不替代排盘正确性、原规则来源核实或实际预测价值的评审。

## 文字块许可表

下表中的占位符由闭合枚举或判断数据填入，不接受任意用户文本。判断类块若全部引用 `quiet` 判断，只能标为 `method_note`；否则为 `interpretation`。

| `templateId` 模式 | 允许条件与文字职责 | 引用范围 |
|---|---|---|
| `focus.{state}` | `leading` 仍按表达强度说话；`tied` 列出全部并列主候选；`none` 不强造主线 | 当年候选；无候选则引用当年有依据的判断 |
| `annual_overview.{path}.{support/mixed/limitation}` | 年度标题只写该公历年最值得关注的流年支持/限制，并区分支持与限制的实际轻重；三年共同关注方向只在总论出现一次 | 当年所选路径及其流年根事实 |
| `income.{path}.{stance}.{strength}[+…]` | 单段一至两条收入路径；支持、混合、受限、无依据分别写；混合不能只留好的一面 | 当年段落涉及的收入判断，保留其支持和限制引用 |
| `retention.{stance}.{strength}` | 说明能否积攒结余及限制，不把结余当作收入来源；与年度风险重复的完整句只展示一次 | 当年留钱判断；删除重复展示不删除判断或依据 |
| `risk.{path}` | 只在存在实际负向时生成，说明该路径已有的限制；标题只能说“需要留意的一项” | 当年该路径判断，风险对象另存全部实际负向引用 |
| `observation.{path}` | 可核对的现实例子，不暗示现象发生就证明预测正确 | 当年适用判断；`kind = observation` |
| `action.{path}` | 日常可做的一件事，不假定用户已经有收入、职业或债务 | 当年适用判断；`kind = general_advice` |
| `comparison.{changed/unchanged}` | 读两年实际比较，不读报告年序；区分正负变化、来源变化、表达许可变化与相对位置变化 | 相邻两年及实际变化路径；无变化则引用延续判断 |
| `thesis.focus_groups` | 按真实年度关注方向分组，相同文字可合并年份，不编三阶段剧情 | 对应年份的关注判断 |
| `path_summary.{path}` | 五路径各一项，逐年按倾向、强度和已有负向条件归组 | 该路径全部年度判断，另存 `yearDecisionIds` |
| `risk_summary.years` | 只汇总实际有风险的年份；全部无风险则整个块为 `null` | 恰好为有风险的年份及对应风险判断 |
| `summary.retention_groups` | 区分收入与结余；存在限制时明确实际年份，不照抄风险正文 | 分析期内留钱判断 |
| `route.{path}` | 一至三条汇总的一般建议；不叙述“前几年已赚到、再扩大” | 分析期内适用判断；`kind = general_advice` |
| `reading_note` | 一次性说明传统规则和观察事项的边界 | 整个分析期；`kind = method_note` |

弱支持不能因为“排第一”就使用更强文案；并列不能靠数组顺序拆成强弱。年度两条建议优先覆盖一个收入关注点和实际风险；这只是篇幅安排，不改变并列判断，完整并列仍在总论和收入段呈现。

## 负向依据到日常用语

只从当前判断的 `limitingEvidenceIds` 找实际负向计分项，不把所有年度依据盲目当成正文来源。

| 已有负向 `factKey` | 可说明的事项，不是已发生事实 |
|---|---|
| `natal.combination.peer_wealth` | 分账、共同开销 |
| `natal.balance` | 新增投入与结余之间的限制 |
| `annual.branch.clash/harm/punishment.*` | 约定变化、临时开销需要防备 |
| `dayun.stem.ten_god` | 与人有关的支出 |
| `annual.stem.ten_god` | 项目要求、付款条件 |

这些只是对既有规则含义的保守转述，不证明现实中已有纠纷、损失或某种职业。明确标注的合成边界缺少上述具体来源时，只能用路径范围内的限制说明；不得给合成计分伪造命盘事实。正常生成链遇到未知必要来源应在来源映射层拒绝，而非用空泛文案放行。

## 年度变化的措辞限制

- 正负分别变化时都要说明，不用净分掩盖“机会和限制一起增加”。
- 依据或事实值变化、总权重相同，可以说明条件变化；不能捏造涨薪、订单数量或获利金额。
- 分数相同但独立来源使表达等级变化，说明关注程度提高或降低，不误写成完全延续。
- 自身条件没变、只是其他路径变了，说明相对位置变化，不宣称本路径自身变好。
- 三年共同结论只在总论集中说明，不能原样占据每年的标题；条件真正延续时在年度比较中说明，不以随机同义词制造差异。
- 当年流年支持或限制确有不同，年度标题应体现最值得阅读的一项差异；同一公历年不得因报告从哪一年开始而换标题。
- 同一路径的年度信号轻重不同，标题必须体现“比较明显”或“存在一些”等真实差别，不能因正负方向相同就合并成同一句。
- 每段直接写下一年的公历年份；跨年归组不把多个年份统一叫“今年”。

## 可执行的文案许可

`WealthPlainCopyV3` 与 `WealthNarrativeWriter` 共同构成闭合许可：枚举路径、倾向、表达强度、已知负向条件及实际年度比较决定正文。每块有固定用途、类型、适用年份、判断引用和模板标识。

`validateDraft` 根据草稿中的事实和依据重新核对判断并重建当前版本文字，要求整份结构一致。因此只改 `templateId`、把强预测改标为 `general_advice`、替换引用、改变文字或分析范围都不能绕过当前草稿校验。不是仅检查字段存在，也不是仅靠禁词过滤。

**此方法只用于本版本新草稿。不能用于历史报告读取或覆盖旧快照。** 文案版本变化后，历史内容仍按已保存原文和版本读取。任务 7 已让 `WealthNarrativeV3` 实现正式 `ReportContent`，并在保存前执行本校验；读取历史 v1/v2/v3 快照时不重跑生成器或校验器。

输出每块最多 240 字符，按句号等分句后每句不超过 48 个汉字；禁用无对象的“卡点/卡住”、职场黑话、固定年序和确定获利措辞。自动检查只是底线，仍需读实际生成样本，不能用测试数代替中文质量判断。

## 产品边界与尚待处理的事项

- 内部生成器支持二至五年；正式业务入口只生成三年。不能把内部五年验证结果当成已经开放五年产品。
- 当前样本审校已去掉留钱与风险段的同句重复；三年共同主线在总论只出现一次，年度标题改为当年信号。真正相同的延续由年度比较说明，不伪造变化。
- 仅有弱信号的样本仍可能价值不足，完整覆盖不等于有可收费的结论。不得通过提高措辞强度解决此问题。
- 权重、旺衰与现实准确性的治理不在本次正文改写中；也没有接入 LLM、用户问卷或支付。当前只完成 H2 快照往返，真实 MySQL 容量与字段适配留到任务 9。
