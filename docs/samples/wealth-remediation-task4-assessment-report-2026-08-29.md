## 1. 本轮完成了什么

本轮没有更换原算法或重写正文，而是在原始计分之后增加独立判断层：明确哪些收入方向有足够支持、哪些限制必须保留，以及依据最多允许说到什么程度。

| 情况 | 新判断层行为 |
|---|---|
| 没有负向计分项 | 风险选择为 `null`，不填入一般理财常识凑风险 |
| 全零、全弱支持或全负分 | 不硬选主要收入方向，五条路径仍保留各自判断 |
| 最高分有多条合格路径 | 保留全部并列主候选，不凭展示顺序拆成主辅 |
| 唯一领先，但第二名不合格 | 辅助候选为空；辅助最高分并列时保留全部合格项 |
| 同一路径既有支持也有限制 | 分别保留正负权重和依据，净分再高也不能改成单面有利 |
| 原局单项与同源组合重复支持 | 保留原计分，但不能冒充两组独立来源升级表达 |
| 不同家族共享根事实，或仅更换根事实 ID | 按实际来源识别重叠，不因标签或改名升级 |
| 来源信息不完整 | 原分数保留、表达从严、该路径不进入收入候选；不补造缺失事实 |

收入方向的候选门槛仍为净分 3。更突出表达还须净分至少 6、没有负向依据，并有两条来自不同来源组且根事实不重叠的支持。原局结构与原局组合属于同一来源组。

这些门槛是既定工程约束，不是新获得的统计结论；“来源不重复”也不等于统计独立。测试通过不能证明命理规则能准确预测现实收入。

## 2. 实现范围与接入边界

新增代码位于 `apps/server/src/main/java/com/bazi/app/report/wealth/v3/`：

| 文件 | 作用 |
|---|---|
| `WealthAssessment.java` | 保存年度根事实、计分项、五路径判断、候选和风险选择；不是完整报告 |
| `WealthAssessmentInput.java` | 内部输入及待核实来源标记，不接受客户端直接传入 |
| `WealthProvenanceResolver.java` | 把现有计分项连接到实际参与条件，保留原始权重 |
| `WealthExpressionPolicy.java` | 独立判断倾向、表达强度、主辅候选及风险，不依赖旧文案 |
| `WealthV3Analyzer.java` | 复用原事实提取和原评分，连接来源映射与新判断 |

完整输入入口为 `WealthV3Analyzer.analyze(chart, contexts)`：技术上支持二至五年；产品常量仍是三年。每年独立判断，相同年度不因位于报告的不同位置或报告总年数而改变结果。

`assess(yearFacts)` 仅供局部分析。旧年度事实未包含所有关系所需的目标地支，因此该入口可能产生待核实来源。缺少资料时不从描述文字猜测地支，也不把单纯的家族标签当作完整来源。

来源映射覆盖原局十神、组合及其参与条件、旺衰限制与财富触发条件、流年/大运十神，以及现有地支关系。给出完整上下文时会核对关系是否成立；未知计分来源、值冲突或错误关系直接报错。

**待核实风险的边界：**负向原始计分不会因来源待核实而被删除，因此内部风险选择仍可能指向这类项。它不是已通过正文许可的风险说明。任务 6–7 必须完成所用依据的核实；缺失必要条件时拒绝生成，不能靠标签或免责声明放行。

本轮内部风险对象只有路径和负向引用，没有最终接口要求的 `reading`。整个判断结果不实现正式 `ReportContent`，也不带 `ready` 状态。未修改 `ReportService`、控制器、前端、正文资源、数据库或正式响应类型。

## 4. 独立规范还剩哪些失败

本轮只把方向和表达强度规范改接真实 v3 判断。评分后的合成边界仅构造显式测试来源，再调用真实策略，不在测试辅助代码中重新排名或生成答案。真实命盘来源测试走实际映射。

`render` 仍读取未修改的 v2 正文，不把新判断与旧文字拼成假新版。因此剩余 15 条失败继续保留：

| 未通过内容 | 条数 | 后续任务 |
|---|---|---|
| 无风险时仍有风险摘要或年度风险文案 | 2 | 6：接入可空风险判断，取消占位风险文字 |
| 弱支持或全受限仍强断主要收入来源 | 2 | 6：正文按表达许可选句 |
| 增加负向后仍用单面有利句、阅读依据遗漏主方向限制 | 2 | 6：正文及引用同时保留两面 |
| 同年度处于不同报告年序时，重点/留钱/观察/行动改变 | 4 | 5–6：独立年度结果，取消年序剧情 |
| 同条件仍造变化、同分不同来源/事实值/正负总量未体现差异 | 4 | 5–6：比较实际依据，再生成对应过渡 |
| 不同收入方向仍复用同一泛化总论 | 1 | 6：总论关联实际年度判断 |

已经通过的旧正向对照继续保留。`Spec` 当前仍需显式运行；没有禁用断言、跳过失败或重写冻结答案，任务 9 要将接入完整 v3 后的规范纳入自动回归。

```sh
mvn -o -Dtest=WealthExpressionPolicyTest,WealthProvenanceResolverTest,WealthRemediationFixtureTest,WealthV2BaselineTest,WealthFactExtractorTest,WealthPathEvaluatorTest,WealthArbitratorTest,WealthNarrativePlannerTest,WealthGoldenCaseTest,ReportHorizonTest -Dwealth.captureAssessments=true test
```

显式运行全部整改规范，目前应以非零状态结束并报告 15 条断言失败：

```sh
mvn -o -Dtest=WealthRemediationSpec -DtrimStackTrace=true test
```

在仓库根目录检查实际 Java 输出及草案：

```sh
node contracts/tests/check-wealth-v3-assessments.cjs apps/server/target/wealth-v3-assessments.json
node --test contracts/tests/wealth-v3-contract.test.cjs
```

`apps/server/target/wealth-v3-assessments.json` 是可重新生成的诊断产物，包含真实判断结果，不含可供消费者审核的新正文；清理构建目录后可按上述命令再生成。字段检查仅复用草案中的事实、依据、判断、候选定义，明确不声称通过完整报告 Schema。
