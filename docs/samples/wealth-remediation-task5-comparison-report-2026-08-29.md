## 1. 本轮结果

现在可以根据两年实际参与判断的依据，区分“条件延续”和“条件发生变化”，并追查具体变了什么。没有修改原权重，也没有按报告的第一、第二、第三年安排收入剧情。

| 情况 | 当前处理 |
|---|---|
| 分数、规则、事实来源及判断状态相同 | 比较结果为延续，差异列表为空 |
| 分数相同，但支持来源或实际事实值改变 | 保留变化，引用本年的旧依据及下一年的新依据 |
| 支持和限制同时增加，净分没有改变 | 分别保存两项差额，不让变化被净分抵消 |
| 某个方向从独自领先变成并列 | 即使自身分数没变，也记录关注角色的变化 |
| 只有年份编号、记录 ID 或排列顺序改变 | 不视为判断变化 |
| 报告起始年或总年数改变 | 相同年度的判断、相同两年的比较保持一致 |
| 到达报告末年 | 到下一年的比较为 `null`，不编造报告范围外的过渡 |

`changed` 只表示数据或判断状态发生变化，不等于“明年变好”，也不等于现实事件必然发生。如何用普通话解释变化，仍是任务 6 的工作。

## 2. 新增模块和比较规则

代码位于 `apps/server/src/main/java/com/bazi/app/report/wealth/v3/`：

- `WealthComparison`：内部比较对象，保留 `toYear / direction / changes`。每条路径差异记录支持差额、限制差额、新增及移除依据引用。
- `WealthAnnualComparator`：比较已经完成的年度判断，不重新选择赚钱方向、不调整任何规则权重。
- `WealthV3Analyzer.analyzeWithComparisons(chart, contexts)`：完整出生计算链路的内部入口，返回原年度判断及相邻比较；既有 `analyze` 返回值不变。

差异匹配使用路径、规则键、来源键、来源家族、原始权重，以及所引用根事实的类型、代码和实际值。ID 只用于查找与引用；不靠截断整段字符串来消除年份，避免误删真实规则或事实值。

支持/限制差额均为“下一年减本年”。同一个来源键的权重或事实值改变时，仍登记两侧记录：移除项属于本年，新增项属于下一年。没有参与计分和判断的事实变化，不单独制造收入变化。

倾向、表达等级、原因码和关注角色也参与比较。例如稳定收入从独自领先变成与能力收入并列，它可以出现零分差、没有新增/移除依据的差异项；解释应读取两年原判断，不能编造一条不存在的新依据。

来源核实状态改变也会影响表达许可。后续正文须区分“能够说到什么程度改变了”和“实际输入条件改变了”，不能把来源资料补齐写成未来机会增强。带有必要来源未核实标记的内部结果仍不得直接发布。

比较前检查连续年份、五条不同路径、根事实引用、重复来源、判断汇总及支持/限制引用；输入不完整时报错，不伪装成“没有变化”。这些是比较所需检查，不能替代任务 7 的完整报告生成校验。

