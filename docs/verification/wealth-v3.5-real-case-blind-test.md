## 这一步验证什么

固定样本已经证明不同证据不会再塌缩成同一段文案，但没有证明回顾与真人经历相符。本轮只验证上一年回顾的现实相关性、明显不符、可读性和模板感。

首批 5 份属于流程试跑，只用于发现问题；30 份才进入小规模门槛判断，100 份才允许报告正式统计结果。不能用 5 份样本宣称明显不符率已经低于 5%。

## 首批 5 份流程

1. 找 5 位出生时间和地点相对确定、愿意独立反馈的受测者。
2. 在受测者讲述去年经历之前生成财富通俗版报告。
3. 将 `/api/v1/reports` 返回的完整报告数组放入 `.private-evals/private-reports.json`，不得提交 Git。
4. 初始化匿名评分骨架：

```bash
python3 e2e/wealth_blind_review.py .private-evals/private-reports.json \
  --init-reports \
  --batch-id wealth-v35-dry-run-001 \
  --commit 1dc9abf \
  > .private-evals/wealth-v35-dry-run-001.json
```

5. 受测者依次评价主判断、次判断、隐性影响和整体，不展示证据键或内部路径名称，也不要由协调人解释后再评分。
6. 填写完成后运行：

```bash
python3 e2e/wealth_blind_review.py .private-evals/wealth-v35-dry-run-001.json
```

## 评分口径

- A 明显相关：资金对象、变化方向和影响能对应明确经历。
- B 部分相关：只有部分对应，或方向接近但对象不够具体。
- C 无法判断：记不清、没有相关场景或句子太宽泛。
- D 明显不符：方向相反，或明确暗示了不存在的资金情形。

B、C、D 必须选择失败原因；C 不能算命中，D 也不能因用户“没感觉”而滥用。首批尤其关注：

- `RULE_DIRECTION_WRONG`：规则方向与经历相反。
- `EVIDENCE_TOO_WEAK`：证据弱但表达过重。
- `OBJECT_TOO_VAGUE`：不知道报告具体在说什么。
- `UNSUPPORTED_ASSUMPTION`：臆测职业、收入方式或不存在的场景。
- `COPY_UNNATURAL`：中文需要猜测。
- `REPORTS_TOO_SIMILAR`：不同报告仍像同一模板。

## 隐私与版本边界

- 姓名、生日、出生时间、出生地点、联系方式和事实说明只放在私有目录。
- 仓库只能提交不含个人信息的聚合结果。
- v3.5 新批次不得混入 v3.4 报告；工具会直接拒绝混合版本。
- 历史 v3.4 批次仍可由当前统计器复算，不修改其原始数据。
- 修改计算、仲裁或文案后必须新开批次，并记录新的提交哈希。
