# 财富 v3.4 真人盲测验收方案

日期：2026-09-05  
适用版本：`wealth-narrative-v4` + `wealth-plain-v3.4`

## 目的

本轮只验证财富报告的上一年回看是否与真人经历有关联、是否出现明显不符，以及不同命盘之间是否产生可感知的差异。

固定测试盘、单元测试和文案检查只能证明结构稳定、没有禁语，不能证明内容与真人经历相符。当前年只能评价“是否有关、是否说得清楚”，未来年份必须等对应年份结束后再做预测验证，不能提前计为准确。

## 验收对象

- 试运行：至少 30 份彼此独立的真人命盘。
- 正式评估：至少 100 份，不能全部来自同一年龄、地区或熟人圈。
- 同一个人、同一个出生信息、同一个主题只计一份，重复生成不能扩充分母。
- 出生时间不确定、出生地点无法解析、真太阳时链路失败的样本单独记录，不混入内容准确性统计。
- R01–R12 和合成边界样本只用于回归，不计入真人盲测。

30 份只能用于发现明显问题，不能据此证明真实不符率稳定低于 5%。正式结论必须同时报告样本数、观察值和置信区间。

## 盲测流程

1. 协调人收集出生信息，并为每人生成随机 `caseId`；出生信息与姓名只保存在不进入 Git 的私有映射表中。
2. 在受测者描述上一年经历之前，固定当前版本生成报告，并记录 `reportId`、`copyVersion`、生成时间和正文哈希。
3. 受测者只阅读用户可见报告，不展示八字证据键、内部五路径名称、候选标题或规则解释。
4. 受测者先独立评价“主判断”，再评价“次判断”和“隐性影响”；不能由协调人解释句子后再评分。
5. 评价完成后才收集一句可核对的事实说明。事实说明只用于复核，不允许反向改写已冻结的本份报告。
6. 对争议项由第二名审核者在不知道首位评分的情况下复核；两人意见不同时标记为“需复核”，不强行计为命中。
7. 当前判断只记录相关性和可读性；未来行动登记为前瞻样本，到期后另行复测。

## 单份评分卡

每份报告必须填写以下字段：

| 字段 | 可选值或填写要求 |
|---|---|
| `caseId` | 随机编号，不含姓名、生日、手机号 |
| `reportId` | 后端报告编号 |
| `copyVersion` | 必须为 `wealth-plain-v3.4` |
| `contentHash` | 冻结正文的 SHA-256 |
| 主判断 | A 明显相关 / B 部分相关 / C 无法判断 / D 明显不符 |
| 次判断 | A / B / C / D |
| 隐性影响 | A / B / C / D |
| 去年整体 | A / B / C / D，必须在三项完成后再选 |
| 当前相关性 | 0 无关 / 1 较弱 / 2 一般 / 3 较强 |
| 中文可读性 | 0 不通顺 / 1 需猜意思 / 2 基本清楚 / 3 一遍看懂 |
| 与其他报告相似感 | 0 不明显 / 1 有少量 / 2 较明显 / 3 像同一模板 |
| 事实说明 | 一句话说明评分依据，不写宽泛感受 |
| 复核状态 | 无需复核 / 需复核 / 已复核 |

评分解释：

- A：描述的资金状态、变化方向和影响都能对应上一年明确经历。
- B：只有一部分对应，或者方向接近但对象不够具体。
- C：受测者记不清、没有相关场景，或句子太宽泛，无法判断真伪。
- D：描述与可核对经历方向相反，或报告明确暗示了不存在的资金情形。

“没感觉”“好像一般”不能直接计为 D；同样，C 也不能计为命中。

## 指标定义

设：

- `N`：全部有效真人报告数。
- `A/B/C/D`：去年整体评分的数量。
- `R`：仍处于争议复核状态的数量。

必须同时公布：

```text
原始明显不符率 = D / N
可判断样本明显不符率 = D / (A + B + D)
可判断覆盖率 = (A + B + D) / N
强相关率 = A / N
模板感偏高率 = 相似感评分 >= 2 的报告数 / N
争议率 = R / N
```

禁止只公布 `A + B` 的“命中率”。B 代表部分相关，不等于准确；C 必须保留在报告里，不能从结果中悄悄删除。

## 阶段门槛

### 30 份试运行

- 原始明显不符率不高于 5%，即最多允许 1 份 D。
- 可判断覆盖率至少 80%。
- 中文可读性平均分至少 2.5。
- 模板感偏高率不超过 15%。
- 不允许出现职业、工资形式、客户、订单、投资方式等输入中不存在的事实推断。

### 100 份正式评估

- 原始明显不符率和可判断样本明显不符率都不高于 5%。
- 同时报告 95% 置信区间；如果区间上界仍高于 5%，只能表述为“本批观察值不高于 5%”，不能宣称真实总体已稳定低于 5%。
- 可判断覆盖率至少 85%。
- 中文可读性平均分至少 2.7。
- 模板感偏高率不超过 10%。
- 按年龄段、性别、出生时间确定性和真太阳时是否跨时辰分别列结果，任何分组不得用总体均值掩盖异常。

## 失败归因

每个 B、C、D 至少选择一个原因：

- `RULE_DIRECTION_WRONG`：规则方向与经历相反。
- `EVIDENCE_TOO_WEAK`：证据不足却输出得过重。
- `OBJECT_TOO_VAGUE`：对象太泛，受测者不知道在说什么。
- `UNSUPPORTED_ASSUMPTION`：推断了职业、收入形式或不存在的场景。
- `COPY_UNNATURAL`：中文不通顺或需要猜含义。
- `REPORTS_TOO_SIMILAR`：不同命盘的核心内容过于相似。
- `BIRTH_DATA_UNCERTAIN`：出生数据不可靠。
- `CANNOT_RECALL`：受测者无法回忆或核对。
- `OTHER`：必须填写说明。

前三类优先修改计算与证据权重；`COPY_UNNATURAL` 才进入文案层。不得用改写文案掩盖规则方向错误。

## 数据与隐私边界

- 真人出生信息、姓名、联系方式和事实说明不得提交到仓库。
- 仓库只允许保存去标识化汇总结果、失败类型计数和不含出生信息的脱敏片段。
- 所有对比必须锁定同一个代码提交和文案版本；版本变化后重新开批次，不能把不同版本混算。
- 当前可接受基线提交为 `009ede1`；后续盲测结果必须记录实际运行提交，不能默认沿用。

## 离线统计方式

仓库提供 `e2e/wealth_blind_review.py`。私人评分文件放在根目录 `.private-evals/`，该目录已加入 `.gitignore`。

```bash
mkdir -p .private-evals
cp e2e/wealth-blind-review.example.json .private-evals/wealth-pilot-001.json
python3 e2e/wealth_blind_review.py .private-evals/wealth-pilot-001.json
```

程序会自动拒绝个人信息字段、重复 `caseId`、重复 `reportId`、错误版本、无失败原因的 B/C/D 评分以及未完成复核的数据，并输出阶段门槛和 95% Wilson 区间。命令行汇总不会回显单份报告正文、事实说明或正文哈希。

若已有 `/api/v1/reports` 返回的财富报告数组，可先初始化匿名评分骨架：

```bash
python3 e2e/wealth_blind_review.py .private-evals/private-reports.json --init-reports --batch-id wealth-pilot-001 --commit 994fa51 > .private-evals/wealth-pilot-001.json
```

输入快照仍可能包含姓名与完整报告，因此只能放在 `.private-evals/`。初始化输出只保留随机 `caseId`、`reportId`、版本、正文哈希和空评分项，不保留姓名与正文。空评分骨架不能通过统计校验，必须由受测者完成评分后再统计。

## 本轮交付判定

拿到首批真人数据前，当前只能视为“结构与表达回归通过”。首批 30 份完成后，才决定下一轮应优先调整规则方向、证据阈值、对象具体度还是文案自然度。
